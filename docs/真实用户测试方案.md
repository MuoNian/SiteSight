# 鹭见 SiteSight · 真实用户测试方案

> 日期：2026-08-21（赛期内第一批真实用户测试）

## 一、测试目的

验证三个核心假设：

1. **能独立完成**：建筑学学生不教就能走通“成果 → AI 报告 → 反馈偏好 → 再生成”的核心流程。
2. **真的有价值**：测试者愿意用它在课程设计/竞赛里做基地分析，而不是“看起来酷但不用”。
3. **反馈被记住**：测试者能理解“记忆 Agent”的价值，并觉得报告越来越贴合自己。

## 二、测试对象

- 1–2 名建筑学/城乡规划专业同学
- 最好近期做过课程设计或竞赛的场地分析
- 无人机经验不限（本次主要测网页端流程）

## 三、测试形式

- 面对面，单次 30–40 分钟
- 在测试电脑（你的电脑）上进行，由测试者操作，你在旁边观察记录
- 鼓励“出声思考”：想到什么说什么
- 征得同意后录音/录屏，方便回看

## 四、准备清单

- [ ] 测试电脑：Python 3.13、OpenDroneMap 3.6.1、项目源码在本地
- [ ] 启动 `scripts\启动鹭见SiteSight.bat`，确认页面打开
- [ ] 准备演示成果路径：`C:\Users\Administrator\Desktop\ODM_Results\project_20260810_155221`
- [ ] 准备 10–20 张小照片文件夹（可选，测快速模式用）
- [ ] 打印或手机打开《测试记录表》
- [ ] 录音/录屏工具（OBS 或手机，先征得同意）

## 五、测试动线（按顺序）

### 动线 A：打开已有成果 → AI 报告（核心，必测）

1. 打开网页，看到“打开已有成果”输入框
2. 粘贴成果路径 → 点“加载成果”
3. 查看成果列表（OBJ / 正射 / DSM / 点云 / 报告）
4. 点开 AI 场地分析报告
5. 观察：测试者能否理解报告内容？哪里看不懂？

### 动线 B：反馈偏好 → 重新生成（记忆 Agent，必测）

1. 让测试者写一条自己的偏好（如“我要做住宅设计，重点写坡度”）
2. 点“记住这条偏好”
3. 点“重新生成报告”
4. 观察：测试者是否注意到新报告参考了偏好？觉得有用吗？

### 动线 C：导出与下游使用（演示级）

1. 下载 OBJ（或导出 STL）
2. 用 Rhino/SketchUp 打开（可以你提前准备好打开过程）
3. 观察：测试者是否知道这些格式能干嘛？

### 动线 D：快速模式（可选，时间够就测）

1. 拖入 10–20 张小照片
2. 勾选“快速模式”，开始处理，看 3–5 分钟出粗模

## 六、访谈问题（开放式）

1. 你平时做基地分析，最常被什么卡住？
2. 刚才整个流程里，哪一步最让你困惑？
3. 哪一步你觉得最有用？
4. 报告里的内容，你愿意直接用进课程设计/竞赛吗？哪里还需要改？
5. “记住偏好”这个功能，对你来说是加分还是无所谓？
6. 如果要花 30 分钟学会它、每次拍照+等待 1 小时，你愿意用吗？
7. 你还会在什么场景用它？（选地、竞赛、毕设、乡村项目…）
8. 如果让你给同学推荐，你会怎么说？
9. 最想砍掉的功能 / 最想要的新功能？
10. 满分 10 分，你愿意给这个工具打几分？为什么？

## 七、衡量指标

- 核心动线（A+B）完成率：全部完成 = 通过
- 平均用时：理想 < 10 分钟（含报告生成等待）
- 主观评分（1–5）：
  - 易用性 ____
  - 有用性 ____
  - 继续使用意愿 ____
  - 推荐意愿 ____
- 关键改进点：每条反馈标注 P0（必须修）/ P1（尽快修）/ P2（以后再说）

## 八、测试后动作

1. 整理《测试记录表》为反馈清单（P0/P1/P2）
2. P0/P1 当天/次日修完，记录到 README 的更新日志
3. 把真实用户反馈写进 8/24 中期材料和最终项目简介（“已完成真实用户验证”是硬加分项）
4. 征得同意后，把测试录屏片段剪进演示视频
