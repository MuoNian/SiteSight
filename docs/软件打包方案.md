# 鹭见 SiteSight · 软件打包方案（待决策）

> 目标：把「鹭见 SiteSight」打包成普通用户能安装、双击即用的 Windows 软件。

## 一、要打包的东西（现状架构）

1. **网页服务**：Python 标准库（server.py + 前端 index.html），零第三方依赖
2. **建模引擎**：OpenDroneMap 原生 Windows 版（约 3–5 GB，当前装在 D:\WebODM（OpenDroneMap）\ODM）
3. **AI 报告**：大模型 API（配置在本地 config.json，**API Key 不进安装包**）
4. **记忆 Agent**：本地 JSON，随用户目录保存

## 二、已确认方案（2026-08-29）

**桌面窗口外壳（决策一 A）+ 引擎全量打包（决策二 A）+ Inno Setup（决策三 A）+ 面向自己电脑和评委机（决策四 A）**

构建工具与脚本已就绪：

- `app/launcher.py`：pywebview 桌面窗口外壳（启动本地服务 + 原生窗口）
- `packaging/make_icon.py`：生成应用图标（品牌等高线 + 琥珀观测点）
- `packaging/build.ps1`：一键构建（装依赖 → 生成图标 → PyInstaller 打包 → 复制 ODM 引擎 → Inno 编译）
- `packaging/SiteSight.iss`：Inno Setup 安装器配置

构建命令（仓库根目录）：

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

安装包输出：`packaging\output\LuJianSiteSight_Setup.exe`

## 三、四个需要拍板的决策点（历史记录）

### 决策一：界面形态

- **方案 A：桌面窗口外壳**（推荐）——用 pywebview 把网页界面包进原生窗口，双击图标打开像真软件，不依赖浏览器标签页
- 方案 B：保持“启动器 + 浏览器”现状，只做安装器和图标
- 方案 C：用 PyQt/Tkinter 重写原生界面（工作量大，不推荐）

### 决策二：建模引擎（ODM）打包范围

- **方案 A：全量打包**（推荐）——安装包 5–8 GB，用户装一次全配好，成功率最高
- 方案 B：只打包 SiteSight 本体（约 50 MB），安装器检测/引导用户单独装 ODM

### 决策三：安装器技术

- **方案 A：Inno Setup**（推荐）——Windows 标准安装器，教程多、稳定、支持卸载
- 方案 B：NSIS
- 方案 C：便携版（绿色解压即用，免安装，但更新和卸载体验弱）

### 决策四：发布范围

- **方案 A：面向“自己电脑 + 评委演示机”**（推荐先做）——固定/可预知环境，打包简单可靠
- 方案 B：面向任意 Windows 10/11 用户——需打包 Python 运行时、处理各种环境差异，工作量翻倍

## 三、技术要点（无论怎么选都要做）

- 用 **PyInstaller** 把 Python 服务打成 exe（不需要用户装 Python）
- 前端页面、图标、启动脚本随包
- **API Key 不内置**：首次启动引导用户填写 config.json（本地保存）
- **ODM 许可证合规**：ODM 是 AGPL-3.0，随包分发需附许可证与源码获取链接（仓库已声明）
- 版本号、README、卸载程序
- 生成日志与错误反馈目录，方便排查

## 四、我的推荐组合

**桌面窗口外壳（决策一 A）+ 引擎全量打包（决策二 A）+ Inno Setup（决策三 A）+ 面向自己电脑和评委机（决策四 A）**

理由：演示最有“产品感”、安装一次成功率高、工程量可控，能在 8/31 提交前完成并作为“安装包”选交项。
